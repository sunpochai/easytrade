# EasyTrade — BTC Recommendation Bot

เว็บภาษาไทยสำหรับอ่านราคาผ่าน API และแนะนำตามกฎวิเคราะห์เทคนิค พร้อมคะแนนเงื่อนไขและผลทดสอบย้อนหลัง ใช้ Python 3.11 ขึ้นไป ไม่ต้องลงไลบรารีเพิ่ม ยกเว้นเมื่อใช้ MT5

**ไม่มีการส่งออร์เดอร์จริง ไม่มีการรับรองอัตราชนะหรือผลกำไร และไม่ใช่โมเดล AI ที่ทำนายความน่าจะเป็น**

## เริ่มใช้งาน API

```powershell
python bot.py
```

เปิด http://127.0.0.1:8766 แล้วเลือก API ราคาจริง / ข้อมูลสาธิต / MT5 และ M15 / H1 / H4 บนหน้าเว็บ (เวอร์ชันใหม่ใช้พอร์ต 8766 เพื่อแยกจากเวอร์ชันแรก)

- BTC: Binance Public Market Data, คู่ **BTCUSDT (Spot)** ไม่ใช้ API key ราคาเป็น USDT ไม่ใช่ USD สัญญาณลงหมายถึงลดสินทรัพย์ที่มีหรือรอ ไม่มีการเปิด Short ใน backtest ของ Spot
- ข้อมูลจริงมีปัญหาจะแสดงข้อผิดพลาดแยกรายสินทรัพย์ ไม่แทนด้วยข้อมูลสาธิต

ตั้ง key ใน PowerShell ของคุณก่อนเริ่มเซิร์ฟเวอร์ (ไม่ส่ง key ในแชต ไม่ใส่ลงในหน้าเว็บหรือ Git):

```powershell
python bot.py --source api
```

โปรแกรมอ่านจาก environment เท่านั้น ไม่อ่าน `.env` อัตโนมัติ หากมีเซิร์ฟเวอร์เดิมอยู่ให้หยุดด้วย Ctrl+C ก่อนเริ่มใหม่

ลองโดยไม่เชื่อมต่อบริการภายนอก:

```powershell
python bot.py --source demo
```

โหมด demo ใช้ข้อมูลสังเคราะห์ทั้งราคาและผล backtest ห้ามใช้ผลนี้อ้างว่าเทรดได้กำไรจริง

## MT5 เป็นอีกทางเลือก

เปิด MT5 และล็อกอินด้วยตัวเอง แล้วรัน:

```powershell
python -m pip install -r requirements-mt5.txt
python bot.py --source mt5 --btc-symbol BTCUSD
```

ใช้ชื่อสัญลักษณ์ตรงกับ Market Watch เช่น BTCUSDm ระบบอ่านแท่งที่ปิดแล้วตั้งแต่ index 1 ไม่ใช้รหัสผ่านในโค้ด MT5 จำลองทั้ง Long/Short เชิงทฤษฎี ไม่ได้ตรวจประเภทสัญญาหรือสิทธิ์การ Short ของบัญชี

## ความหมายของเปอร์เซ็นต์

1. **คะแนนเข้าเงื่อนไข**: ผลรวมคะแนนกฎที่ผ่าน ไม่ใช่โอกาสกำไร และไม่ใช่ confidence ของ AI
2. **อัตราชนะย้อนหลัง**: จำนวนเทรดที่มีกำไรสุทธิหลังต้นทุนหารด้วยจำนวนเทรดปิด แสดงจำนวนเทรดและช่วง Wilson 95% ประกอบ (สมมติผลเทรดเป็นอิสระ ซึ่งอาจไม่จริง)
3. **กำไรสุทธิพอร์ตจำลอง**: เปอร์เซ็นต์เปลี่ยนแปลงจากทุน 10,000 หน่วยต่อสินทรัพย์ แต่ละช่วงเริ่มพอร์ตใหม่ ไม่ใช่กำไรต่อเดือนหรือผลตอบแทนคาดการณ์
4. **ระยะราคา Target/Stop**: เปอร์เซ็นต์ห่างจากราคาปิดอ้างอิง ไม่ใช่กำไร/ขาดทุนของทั้งพอร์ต

คะแนนขั้นต่ำเริ่มต้น 85% เงื่อนไขบังคับคือแนวโน้ม, RSI, ราคาไม่ยืดเกิน 1.5 ATR และภาพใหญ่ แม้คะแนนรวมถึงเกณฑ์แล้วก็ตาม กฎนี้เป็นสมมติฐานที่ยังต้องประเมิน ไม่มีการปรับแต่งเพื่ออ้างกำไรสูง เกณฑ์ตัวเลขทั้งหมด (0.03%, 0.5–2 เท่า, วันหยุด) ตั้งจากเหตุผลล่วงหน้า ไม่ได้เลือกจากผลย้อนหลัง

**ตัวระงับสด (live guards)** ตรวจเฉพาะตอนอ่านหน้าเว็บ ไม่ให้คะแนนและไม่อยู่ใน backtest เพราะไม่มีประวัติย้อนหลังให้ทดสอบ หากติดตัวใดตัวหนึ่ง สัญญาณที่ผ่านเกณฑ์จะถูกเปลี่ยนเป็น WAIT พร้อมบอกเหตุผล:

- สเปรด order book Binance Spot ต้องไม่เกิน 5 bps (ปกติต่ำกว่า 1 bp; กว้างกว่านั้นแปลว่าสภาพคล่องบางหรือตลาดกำลังปั่นป่วน)
- ไม่อยู่ในช่วง 60 นาทีก่อนถึง 120 นาทีหลังเหตุการณ์ใน `events.json` (ใส่วันแถลง FOMC ปี 2026–2027 ไว้ให้ ตรวจกับ federalreserve.gov แล้วเมื่อ 2026-09-22 แต่ Fed ระบุว่าทุกวันเป็นกำหนดการชั่วคราว เพิ่ม CPI/NFP เองได้ รูปแบบเวลาเป็น UTC) เปลี่ยนไฟล์ด้วย `--events path.json`

**ข้อมูลสดที่แสดงประกอบ** (ไม่ให้คะแนน): Open interest ของ Binance Futures เทียบ 24 ชม. ก่อน, สัดส่วน bid/ask ในกรอบ ±0.5% ของราคากลาง, BTC dominance จาก CoinGecko (ถ้าถูกจำกัดความถี่จะใช้ CoinPaprika แทน) และการเปลี่ยนแปลง ETH/BTC 20 วัน แต่ละตัวโหลดแยกกัน ตัวใดล้มเหลวจะแสดงข้อผิดพลาดของตัวนั้นโดยไม่กระทบสัญญาณ (ยกเว้น order book ซึ่งเป็นตัวระงับ: อ่านไม่ได้ = ระงับ)

**Funding rate** ใช้ค่าที่ชำระแล้วครั้งล่าสุดก่อนหรือพร้อมเวลาปิดแท่งที่วิเคราะห์ ทั้งหน้าเว็บและ backtest (ประวัติ 1,000 ครั้งราว 333 วัน ครอบคลุมทุกกรอบเวลา) แหล่ง MT5 ก็ใช้ funding ของ Binance เพราะเป็นสัญญาณของตลาด BTC โดยรวม หากโหลดไม่ได้เงื่อนไขนี้ไม่ผ่านและแจ้งสาเหตุ ไม่ใช้ค่าอื่นแทน

**ภาพใหญ่** ใช้กรอบเวลาถัดขึ้นไปหนึ่งขั้น (M15→H1, H1→H4, H4→D1) โดยดูเฉพาะแท่งกรอบใหญ่ที่ปิดแล้วก่อนหรือพร้อมกับแท่งที่กำลังวิเคราะห์ ทั้งหน้าเว็บและ backtest จึงไม่เห็นแท่งกรอบใหญ่ก่อนมันปิดจริง หากโหลดกรอบใหญ่ไม่ได้ ระบบจะไม่ให้สัญญาณและบอกสาเหตุ ไม่ใช้ข้อมูลอื่นแทน

**ปริมาณซื้อขาย** คือสัดส่วนปริมาณของแท่งที่ปิดบวกต่อปริมาณรวมของแท่งที่ปิดบวกและปิดลบใน 20 แท่งล่าสุด ใช้ปริมาณจาก Binance (หน่วย BTC), MT5 (tick volume) และข้อมูลสาธิต หากแหล่งใดไม่ส่งปริมาณ เงื่อนไขนี้จะไม่ผ่านและแสดงว่า "ไม่มีข้อมูลปริมาณ"

Stop ห่าง 1.5 ATR และ Target ห่าง 3 ATR จากราคาปิดอ้างอิง คะแนนอาจคงเดิมหลายแท่ง ไม่ควรตีความว่าต้องเปิดเพิ่มทุกการรีเฟรช หากข้อมูลปิดแท่งล่าสุดเก่าเกิน 2 เท่าของกรอบเวลา จะระงับคำแนะนำ

## วิธี backtest และข้อจำกัด

- ขอข้อมูลล่าสุดสูงสุด 1,000 แท่ง ตัดแท่งยังไม่ปิด ช่วงเวลาทดสอบจะแสดงบนหน้าเว็บ
- แบ่งตามเวลา 70/30 โดยช่วงแรกหัก 200 แท่ง warm-up; ช่วงล่าสุดใช้ประวัติเดิมเพื่อตั้งต้นอินดิเคเตอร์ แต่เริ่มพอร์ต/สถานะใหม่
- ใช้กฎชุดเดียวทั้งช่วงเรียนรู้และช่วงกันไว้ **ไม่ได้ฝึกหรือเลือกพารามิเตอร์จากข้อมูล** การดูผลซ้ำและปรับกฎด้วยตัวเองอาจทำให้ช่วงล่าสุดไม่ใช่ข้อมูลที่กันไว้จริงอีกต่อไป
- สัญญาณจากแท่งปิด เข้าได้ที่เปิดแท่งถัดไปเท่านั้น ไม่ใช้ข้อมูลอนาคตในการสร้างสัญญาณ
- ครั้งละหนึ่งสถานะต่อสินทรัพย์ ตั้งขนาดให้ขาดทุนถึง Stop รวมต้นทุนประมาณ 0.5% ของ equity และจำกัดมูลค่าสถานะ 1 เท่าของทุน
- ค่าธรรมเนียมเริ่มต้น 10 bps/ข้าง และ slippage รวมครึ่งสเปรด 5 bps/ข้าง เป็นสมมติฐาน ไม่ใช่อัตราค่าบริการที่ตรวจจากบัญชี (1 bp = 0.01%)
- Stop/Target อ้างอิงแผนจากราคาปิดก่อนหน้า ยกเลิกการเข้าหากราคาเปิดหลัง slippage อยู่นอกแผน
- Gap ข้าม Stop ออกที่ราคาเปิดที่แย่กว่า; แตะ Stop และ Target ในแท่งเดียวกันถือว่า Stop ก่อน; Gap ข้าม Target ให้ราคา Target อย่างอนุรักษนิยม
- ปิดเมื่อสัญญาณตรงข้ามที่เปิดแท่งถัดไป หรือครบ 48 แท่งที่ราคาปิด หรือปิดท้ายช่วงทดสอบ ขาดทุนจริงจาก Gap อาจเกินงบความเสี่ยง
- Drawdown วัด liquidation equity ที่ราคาปิดแต่ละแท่ง ไม่ใช่ intrabar drawdown หน้าเว็บแสดงเส้นมูลค่าพอร์ตจำลองของช่วงล่าสุด และของช่วงแรกใน "เปรียบเทียบช่วงเวลา" (สุ่มตัวอย่างไม่เกินราว 240 จุดต่อช่วง ค่าเต็มอยู่ใน JSON)
- กราฟทุกตัวชี้เมาส์เพื่อดูค่าที่แท่งนั้น หรือกด Tab ไปที่กราฟแล้วใช้ลูกศรซ้าย/ขวา, Home/End
- ไม่รวมต้นทุน Swap/Funding, ภาษี, เวลาแฝง, lot step, margin call และสภาพคล่องจริง (funding ใช้เป็นเงื่อนไขกรอง ไม่ได้หักเป็นต้นทุน)
- ตัวระงับสด (order book, ปฏิทินประกาศ) ไม่อยู่ใน backtest ผลย้อนหลังจึงอาจมีเทรดที่หน้าเว็บสดจะระงับ
- ถ้ายังมีเทรดน้อยกว่า 30 จะแจ้งว่าหลักฐานยังน้อย จำนวนเกินเกณฑ์ก็ไม่ได้ยืนยันว่ากลยุทธ์จะได้กำไร

ปรับสมมติฐานตอนเริ่มโปรแกรมได้:

```powershell
python bot.py --min-score 85 --risk-pct 0.5 --fee-bps 10 --slippage-bps 5 --port 8766
```

## ติดตั้งเป็นแอปบนมือถือ (PWA)

หน้าเว็บมี manifest, ไอคอน และ service worker แล้ว เมื่อเปิดผ่าน HTTPS (เช่นบน Render) จึงเพิ่มลงหน้าจอหลักได้

- **iPhone/iPad**: เปิดใน Safari > ปุ่มแชร์ > "เพิ่มไปยังหน้าจอโฮม" จะเปิดเต็มจอโดยไม่มีแถบเบราว์เซอร์ และอ่านค่าใหม่ทุกครั้งที่กลับเข้าแอป
- **Android/Chrome**: เมนู > "ติดตั้งแอป" หรือ "เพิ่มไปยังหน้าจอหลัก"
- service worker แคชเฉพาะไฟล์หน้าเว็บ ไม่แคชข้อมูลราคาและผลวิเคราะห์ (`/api/*`) ถ้าออฟไลน์จะเปิดหน้าได้แต่ขึ้นว่าเชื่อมต่อไม่ได้ ไม่แสดงคำแนะนำเก่า
- **การอัปเดตเวอร์ชัน**: ทุกครั้งที่เปิดแอปหรือสลับกลับมา แอปจะสั่งตรวจ service worker ใหม่ เมื่อมีเวอร์ชันใหม่จะรีโหลดหน้าเองหนึ่งครั้ง ท้ายหน้าแสดง "กฎ …" (เวอร์ชันของเซิร์ฟเวอร์) กับ "หน้าเว็บ …" (เวอร์ชันของไฟล์ที่กำลังใช้) ถ้าไม่ตรงกันแอปจะแจ้งและอัปเดตให้ หากยังค้างให้ปิดแอปแล้วเปิดใหม่ หรือลบแล้วเพิ่มลงหน้าจอโฮมอีกครั้ง
- เมื่อแก้กฎต้องเปลี่ยน `VERSION` ใน `strategy.py`, `sw.js` และ `UI_VERSION` ใน `app.js` ให้ตรงกัน (มีเทสตรวจ)
- Safari ต้องเปิดจาก HTTPS หรือ localhost เท่านั้น ใช้ IP ในวง LAN แบบ http จะเพิ่มลงหน้าจอได้แต่ไม่มี service worker

## นำขึ้นโฮสต์ (ไม่บังคับ)

ค่าเริ่มต้นผูกกับ 127.0.0.1 เปิดได้เฉพาะในเครื่อง หากจะให้เข้าจากภายนอกต้องระบุ `--host 0.0.0.0` และระบบจะอ่านพอร์ตจากตัวแปร `PORT` ที่โฮสต์กำหนดให้อัตโนมัติ

- **Render**: มี `render.yaml` ให้แล้ว สร้าง Git repo, push ขึ้น GitHub แล้วสร้าง Blueprint จาก repo นั้น แผนฟรีจะหลับเมื่อไม่มีคนใช้ 15 นาที
- **Docker / Hugging Face Spaces / Cloud Run**: ใช้ `Dockerfile` ฟังพอร์ต 7860 ตามค่าเริ่มต้นของ Spaces หรือกำหนด `PORT` เอง
- **Cloudflare Tunnel**: รันในเครื่องตามปกติ (ไม่ต้องเปลี่ยน host) แล้วชี้ tunnel ไปที่ http://127.0.0.1:8766 เหมาะเมื่อยังใช้ MT5

ข้อควรระวัง: หน้าเว็บไม่มีรหัสผ่าน ผู้ที่มีลิงก์จะอ่านได้ แหล่ง MT5 และ demo ใช้ได้เฉพาะในเครื่อง เลือกภูมิภาคนอกสหรัฐเพราะ Binance จำกัด IP สหรัฐ

ตั้งความเสี่ยงได้มากกว่า 0 ไม่เกิน 2%; ต้นทุน 0–100 bps ต่อข้าง; เกณฑ์คะแนน 70–100 ระบบไม่เพิ่ม leverage เพื่อพยายามสร้างเปอร์เซ็นต์กำไรสูง

## API ของบอท

```text
GET /api/health
GET /api/analysis
GET /api/analysis?source=api&timeframe=H1
GET /api/analysis?source=demo&timeframe=H4
```

ผล JSON มี `assets[].action`, `score`, `checks`, `stop`, `target`, `evidence` และ `backtest.earlier` / `backtest.holdout` พร้อมสมมติฐานและรายการเทรดล่าสุด ดาวน์โหลด JSON ได้จากหน้าเว็บเพื่อเก็บผลตรวจสอบ

API ภายนอก cache 5 นาทีต่อแหล่ง/กรอบเวลา เพื่อลดการใช้โควตา หน้าเว็บรีเฟรช 60 วินาทีและแสดงเวลาปิดแท่งกับเวลาที่ดึงข้อมูล ข้อมูลที่ดึงไม่สำเร็จไม่ถูกใช้ต่อเงียบ ๆ API key ไม่ถูกส่งออกใน JSON หรือแสดง exception URL

บริการ bind เฉพาะ `127.0.0.1` ไม่มีระบบยืนยันตัวตนสำหรับเปิดใช้งานสาธารณะ

## ตรวจสอบโค้ด

```powershell
python -m unittest -v
node --check app.js
```

ทดสอบการไม่ใช้ข้อมูลอนาคต, เข้าแท่งถัดไป, ต้นทุนสองข้าง, gaps, same-bar ambiguity, การปิดด้วยสัญญาณตรงข้าม, Spot ไม่ Short, แยกช่วงทดสอบ, API cache/error/key redaction และ HTTP endpoints การทดสอบผ่านไม่ได้แปลว่ากลยุทธ์ทำกำไร
